- computer use の承認ダイアログを改善: 各アプリのアクセスレベルとよりわかりやすい警告を表示するようになりました
- セッション間メッセージングを改善: クラウドセッションや別のコンピューターが一覧にない場合、Claude が Remote Control がオフであることを説明するようになりました
- `claude -p` のテキスト出力を改善: 他のセッションからのメッセージが保留または破棄された場合、その旨と許可方法を標準エラー出力（stderr）に出力するようになりました
- 公開したアーティファクトを開くことができるユーザーについての Claude の回答を改善: 前回の公開時の回答を繰り返すのではなく、アーティファクトを再確認するよう Claude に指示されるようになりました
- 再開されたセルフホストランナーセッションを改善: Claude が以前の作業がまだ残っているかを確認し、何が欠けているかを報告するようになりました
- サードパーティプロバイダー上の Opus 4.6 および Sonnet 4.6 の plan mode と Bash プロンプトを、より新しいモデルと同様に auto mode を使用・提示するように変更。`disableAutoMode` で両方をオフにできます
- Code Mode を変更し、管理対象のものを含め、スクリプトの出力に対して UserPromptSubmit フックを実行しないようにしました。出力を編集・墨消しするには、`updatedToolOutput` を指定した PostToolUse フックを使用してください
- 大半のモデルにおいて、`/code-review` がバグおよび CLAUDE.md 違反のみを報告するように変更。再利用、簡素化、効率化のクリーンアップには `/simplify` を実行してください
- 大半のモデルにおいて、`/code-review` が各指摘事項に Important、Pre-existing、Nit のマークを付け、各サマリーの最後に修正案を提示するように変更。問題のないレビューの一覧には「Code review found no issues.」と表示されるようになりました
- `claude.ai <name>` 形式の `deniedMcpServers` エントリが、クラウドセッションおよびセルフホストランナーセッションのそのコネクタにも適用されるように変更
- 管理対象の `PostToolUse` フックが、実行前に拒否された呼び出しに対してトリガーされないように変更（ログエントリ、書き換え、ブロック、停止は行われません）。`PostToolBatch` は拒否としてマークされずにその大半を受け取ります
- 送信前に `/bug` が Yes または No を確認するように変更。これにより、Enter の連打で誤ってレポートが送信されたり GitHub が開いたりすることがなくなりました
- `CLAUDE_CODE_FORK_SUBAGENT=0` が設定されている場合、`claude -p`、Agent SDK、デスクトップ、および VS Code 内のサブエージェントが、デフォルトで自身のサブエージェントを待機するように変更
- `CLAUDE_CODE_FORK_SUBAGENT=0` を指定した `claude -p` において、バックグラウンドサブエージェントとそれが待機するサブエージェントを合算して 1 回の 10 分間の待機枠としてカウントするように変更。より長いチェーンの場合は `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` の値を引き上げてください
- PermissionRequest フックによってサンドボックス除外コマンドへと書き換えられたシェルコマンドが、サンドボックス外で実行されるように変更
- permission mode または `/permissions` 内のルールによる回答がある場合を除き、Claude がサイト上でアクションを起こす前に Claude Code が確認を行う旨を、Claude in Chrome のウェルカム画面および `/chrome` に表示するように変更
- サードパーティプロバイダー上、またはテレメトリや機能フラグが無効な環境における Claude Desktop および Agent SDK セッションで、質問が開いた状態で閉じられた際に、無回答のまま継続するのではなくターンを終了するように変更
- サードパーティプロバイダー上、またはテレメトリや機能フラグが無効な環境において、貼り付けられたテキストが Claude に対して貼り付けられたものであるとマークされるように変更
- Anthropic API を使用したターミナルセッションにおいて、サブエージェントの進捗サマリーが短いメモからデフォルトの小型高速モデルによって作成されるように変更（テレメトリ無効時も同様）。消費トークンが大幅に削減されます
- `sandbox.failIfUnavailable` が設定されている場合を除き、起動できないサンドボックスの報告方法を変更: 次のサンドボックス化された Bash コマンドが拒否され、そのセッションでサンドボックスが無効であることが通知されます
- `/list-agents` がリストをユーザーにのみ表示するように変更。Claude は必要な場合に自身でセッションを一覧表示します
- Self-hosted runner: 設定で Claude の GitHub ツールが名前によって保護されている場合、組み込みの `gh api` をデフォルトでオフにするよう変更。`--use-anthropic-gh true` で有効になります
- Self-hosted runner: セッション自体の `claude` が起動する前、または終了した後にラッパースクリプトが実行する `claude` には、Anthropic 管理の git を適用しないように変更
- Self-hosted runner: `CLAUDE_RUNNER_SESSION_UUID` と `CLAUDE_CODE_REMOTE_SESSION_UUID` の両方が、セッションおよびその `checkout`、`post-session`、`spawn-runner` フックに設定されるように変更
