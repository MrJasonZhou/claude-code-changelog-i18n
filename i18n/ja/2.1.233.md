- `--worktree` フラグおよび `claude agents` ビュー（MR が `!N` として表示される）における GitLab マージリクエスト URL のサポートを追加
- Anthropic アップストリームにオプトインの `forward_user_identity` apps gateway 設定を追加。サインインしたユーザーの ID をヘッダーとして送信し、ゲートウェイ背後のプロキシがユーザーごとの利用料を割り振れるように改善
- Linux 上の Bash ツールコマンド向けにオプトインのメモリ cgroup サポート（`CLAUDE_CODE_TOOL_MEMORY_LIMIT`）を追加し、暴走したビルドによってセッションがストールしないように改善
- WebFetch セッションの URL キャッシュ TTL を設定するための環境変数 `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` を追加（デフォルトは変更なし: 15分）
- Claude が権限確認プロンプトを待機している間に環境がシャットダウンした場合、クラウドセッションが喪失（lost）と判定されることがある不具合を修正
- 一定のタイムアウトで長時間接続ストリームを切断するサーバー（サーバーレスホストなど）に対して、MCP v2 接続が subscriptions/listen ストリームを際限なく再オープンし続ける不具合を修正
- Claude Desktop または VS Code 配下で実行されている際、権限確認プロンプトに対して Notification フックが発火しない不具合を修正
- Linux でサンドボックスが有効な場合、アイドル状態のセッションが 1 つの CPU コアを 100% のまま消費し続けることがある不具合を修正
- ユーザーまたはプロジェクトのスキルが同梱スキルをシャドウしている場合、`-p` モードまたはプラグイン/MCP ロード時に `/checkup` や `/review` などの同梱スキルエイリアスが「Unknown command」と表示される不具合を修正
- 引数の値がテンプレートマーカーとして再展開されるのを防ぐため、スキル/コマンドの引数置換処理を修正
- NT デバイスプレフィックス `\??\` を含む Windows パスが UNC パス検証をバイパスする不具合を修正し、NTLM 認証情報の漏洩ベクターを解消
- `claude self-hosted-runner` のセッション開始時間を改善: ワーキングツリーを書き換えることなくセッションブランチが作成されるようになり、2 回のサーバーラウンドトリップがエージェントの起動をブロックしなくなりました
- apps gateway のエラー転送を改善: Vertex、Foundry、および Claude Platform on AWS アップストリームからの 400/413 エラーにアップストリーム独自のエラーメッセージが含まれるようになり、apps gateway における auto-compact のバグを修正
- 単体の `.claude/skills` ディレクトリをチェックするように `claude plugin validate` を改善し、フロントマターの解析に失敗した SKILL.md ファイルを報告するように変更
- スクリーンリーダーモードを改善: `/effort` セレクターが番号付きリストと数字入力プロンプトとして描画されるようになり、ヒントやダイアログのテキストが切り詰められなくなりました
- プリントモードの診断機能を改善: Claude Code が認識しないモデル ID に対してリクエストが送信された際、stderr に `[claude-code:unrecognized_model]` 行を出力（非表示にするには `modelOverrides` でマップ）
- origin リモートが gitlab.com または bitbucket.org 上にあるリポジトリでは GitHub アプリのセットアップヒントが表示されないように変更。Enterprise Marketplace のヒントが GitHub 以外の社内 Git ホストもカバーするようになりました
- Todo/タスク追跡ツール（TaskCreate/Get/Update/List、TodoWrite）が Opus 4.8、Sonnet 5、Fable 5、Mythos 5、およびそれ以降の新しいモデルで利用不可に変更。再度有効化するには `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定してください
- Windows: 通常の `cd <dir> && <command> > file` Bash コマンドで auto モードが手動承認のために繰り返し停止する不具合を修正（2.1.232 のリグレッション）
- Windows 上の Cygwin 形式のシンボリックリンクおよび入力リダイレクト（`< file`）に関する 2.1.232 の Bash 権限の変更を元に戻しました。より対象を絞り込んだバージョンが今後のリリースで再導入される予定です
